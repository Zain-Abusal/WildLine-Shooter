# WILDLINE — shared agent instructions

## Scope and current milestone

Build a lightweight, deterministic, mobile-first open-world combat prototype. The current milestone is a playable Canvas 2D foundation with 2.5D art, multiple game modes (including a looting battle royale) and browser-hosted multiplayer; it is a prototype, not a production competitive service. Read README.md and PROJECT_PLAN.md before changing architecture. Update these files when behavior, verification status, or plans change.

## Engineering rules

- Runtime: pure TypeScript and native Canvas 2D. No Three.js, Phaser, React, or heavyweight game engines.
- One requestAnimationFrame owner: GameEngine. Separate update(dt) and render(ctx). Fixed 60 Hz simulation, capped catch-up, pause on hidden tab.
- Skip chunk streaming scans while padded integer bounds are unchanged; invalidate on world reset. Skip scene redraws in static menus/paused play, invalidating on resize/reset/pause transitions. Cache expanded map terrain by seed/relief and avoid drawing the hidden diagnostics graph. Compute local-player concealment once per enemy update.
- Sound uses a fixed Web Audio bank built once on a user gesture (src/audio.ts): 6 looping-noise voices, 6 tone voices, wind + gust LFO, bird and storm-rumble voices (9 oscillators), master gain and compressor. Re-trigger envelopes only; never create nodes per sound. Every firearm has its own layered shot recipe (e.g. shotgun boom + pellet spread, longshot crack + echo) and other combatants' shots use distance falloff and stereo pan. Ambient updates run in throttled HUD work. Preserve silent fallback and the visible mute toggle. Canvas muzzle/hit/damage effects use existing timers/pools.
- Preallocate all simulation storage. Use Pool for projectiles, particles, and fighters; never grow pools during play. Pool exhaustion drops new spawns safely.
- No new objects, arrays, closures, random generators, collection growth, or string formatting in simulation/scene-render hot paths. Throttled DOM telemetry and browser Canvas internals are exceptions; do not promise zero browser GC without profiling.
- World generation is coordinate-hashed and seed-based; never use Math.random() for layout, drops, or fighter spawn locations (crypto randomness is acceptable on the authority). Keep generation independent of chunk traversal order. Biomes (forest/snow/desert, biomeAt) set terrain palette and props; surface rules keep objects out of water and trees off shores; structures (slots 0 and 3) on dry, flat ground with doorstep caches, rare in the wild and clustered into villages by a settlement noise field (chunk.chest marks battle-royale chests); rocky mountains on high ground; biome rock variants; rare ground medkits. Props keep a chunk-edge margin and minimum spacing; a final surface pass runs after structure placement. Spawns (authority and offline) use blockedSpot to avoid water and buildings. The trail renders bridges over water and the camp is skipped when wet. Supply caches are point gems (points only, no healing); healing comes only from medkits. Points (KILL_POINTS per elimination, caches, harvesting, captures) convert to coins at round end via pointCoins (capped). Shots have weapon-scaled recoil and glowing tracers; characters animate feet while moving and flash when hit; hits show pooled damage numbers (precomputed strings; the authority's hit message carries x/y/d). Client and authority must keep identical Chunk.generate results.
- Chunk objects are fixed reusable slots. Deactivate/recycle distant slots and process only viewport plus one-chunk padding. GPU/canvas backing store and chunk capacity must remain bounded.
- Maintain the bounded edit journal. Document its retention limit; do not silently turn it into an unbounded Map.
- First entry on a device shows a skippable, interactive tutorial (replayable from the pause menu); it hides toasts while visible and must not overlap HUD controls on any layout. The start screen shows and edits the callsign (2–16 letters, numbers, spaces, _ or -), shared with the Party form and saved on the device. Public matches found from Party → Find Public Match enter the game immediately, and the world streams around the camera as soon as a match is joined.
- Keep the tactical HUD and visible ammo, health, kills and player counts. Default start actions are Public and Party. Public auto-enters matchmaking; empty online slots fill with bots and humans replace those slots. If connectivity is unavailable, explicitly label the fallback Bot Practice; never imply offline bots can receive remote players. Practice remains available under Party → Create. Keep Escape, Party and Shop/Locker separate. Compact map expands on click/tap and shows only self + living teammates, never opponents.
- Generation is seeded and reproducible in code, but seed/relief/density controls are removed from player UI, including dev mode. The hidden legacy DOM fields are internal compatibility only. Accepted URL queries: `?dev-mode=true` (diagnostics/PERF plus BOT/HUMAN tags above combatants) and `?god-mode=zrax`, which only arms the developer tools (src/god.ts): the L key opens them after a one-time per-device password check that stores and compares only salted SHA-256 hashes (never commit the password or the device proof, including in tests). Full god tools work offline and in matches this browser hosts, through the authority's admin channel (accepted only from the hosting browser's local connection, never in a public match with another real player); in other hosts' private parties only ESP/aim assist apply; public matches with other humans disable them. The god-mode flag is removed from the URL; no other query enables gameplay overrides. Every new game receives a fresh crypto seed. Keep FPS in a corner. Match area: storm starts at STORM_START_RADIUS (3000), holds STORM_HOLD then closes over STORM_CLOSE; battle royale uses BR_START_RADIUS (7000) / BR_HOLD / BR_CLOSE (src/combat.ts); never hardcode those numbers elsewhere. Sprint (Shift / full-stick push) multiplies speed by SPRINT_MULTIPLIER while stamina lasts; the authority mirrors stamina when validating movement. Land speed is direction independent (235); water below -0.24 slows to 145.
- Public uses its own Matchmaking overlay and cancellation; never flash Party onboarding on primary Public play. Backdrop clicks close/cancel menus through their normal close handlers. Fullscreen belongs in the header, outside the ammo/touch HUD. Use the native mouse crosshair on the canvas; never restore the fixed center marker. Clear pointerAim when switching to touch.
- Game modes live in src/match.ts: teams (default, 15 v 15), br (solo last one standing), ffa (respawns, first to FFA_KILL_TARGET or timer), ctf (respawns, first to CTF_CAPTURE_TARGET captures or timer). Mode selection belongs to Private setup only; public authority forces teams. Use hostile()/network.ally() for every friend/foe check, never raw team equality. Offline practice supports teams and br only and must say so for ffa/ctf. Battle royale: everyone (bots included) starts with only the axe (UNARMED) and only outfits carry over from the Locker; ~30% of caches plus structure doorsteps are chests dropping a rarity-weighted gun with ammo and sometimes a medkit (seeded per chest); spawns are scattered far apart; unarmed bots seek chests; offline enemies hold fire during BR_HOLD.
- Bot toggle and Relaxed/Standard/Veteran difficulty belong to Private setup only. Public authority forces bots on, standard generation and finite ammo; public bot difficulty follows the creator's matchmaking bracket (TIER_DIFFICULTY). Brackets come from device-local games played (src/profile.ts tierFor); public matchmaking prefers the same bracket and never pairs brackets more than one apart. Bot hits use a capped share of their weapon's damage. Respawn modes grant a 2 s spawn shield that ends on attack. No-bot private solo play waits/explores without instant victory; human joiners balance opposite sides. Skip AI until a ready human starts the match. Keep spawn sectors/separation checks and local radial rosters independent of chunk traversal, with different patrol radii and separation steering.
- Leaderboard is horizontal (your team | team score | enemy team; solo modes show ranks and your placement) with fixed 60 DOM rows (30 per side) and only rebuilds its text in throttled UI work while open. The HUD counts only living enemies as players left. Keep the kill feed bounded to four rows with eight-second expiry. Authority emits serial-numbered elimination events; the client deduplicates them and awards each kill once, with snapshot reconciliation that never decreases a round's kills. Preserve killer/victim/actual weapon labels. A human who hit the victim within ASSIST_CREDIT_SECONDS owns a kill finished by a bot or the storm (server and offline); allied bots leave a human's recent target alone unless it comes within 220 units.
- Keep touch controls fixed to the viewport; use Pointer Events for mouse, pen, and multi-touch. Handle cancellation, blur, resize, and visibility. Support simultaneous move/aim/attack on iPad.
- Keep DPR capped at 2 and effective world viewport bounded. Never resize backing canvases each frame.
- Gameplay must continue to work with external fonts unavailable.
- Vercel hosts everything by default: the static client plus api/signal.ts. Without VITE_MULTIPLAYER_URL, a player's browser hosts the match: src/authority.ts runs in src/authority.worker.ts and peers connect over WebRTC data channels (src/p2p.ts); /api/signal only exchanges short-lived listings/offers/answers (src/signal.ts; Redis via REDIS_URL/KV_URL using the pinned `redis` client, or REST via KV_REST_API_* / UPSTASH_REDIS_REST_*; memory store only in dev). Vercel Functions cannot hold the authoritative room process (connections are not pinned to one instance and are cut at max duration), so never move the authority into a function. Host migration: the Worker authority sends a once-per-second backup (serializeRoom, timers stored relative) to one remote player; when the host's tab closes it closes channels and unregisters, the successor restores the room in its own Worker and reclaims the listing with the shared token, and every player reclaims their slot with a private resume token (pending slots return to bots after 30 s). Clients keep the match on screen while migrating and never reset the world on a resumed welcome. Strict NATs may need a TURN relay (VITE_TURN_*). Offer polling backs off when idle to stay within free Redis quotas. `npm run multiplayer` + VITE_MULTIPLAYER_URL remains an optional dedicated server (Dockerfile/render.yaml). Matchmaking retries stale listings and falls back to hosting.
- Player-facing Party onboarding starts with exactly two Create / Join choices. Create then shows callsign and Private/Public visibility; Join shows callsign, friend code, and Find Public Match. Keep Back navigation and a distinct connected view. Do not expose server URLs or transport setup in the UI. Configure connectivity only through deployment configuration. Party members become combat targets only after entering the game.
- Health bars must stay above characters and render after canopies. Preserve the original HUD without the large introductory title.
- Server bots: weapon-aware preferred range (PREFERRED_RANGE), strafing, a reaction delay on new targets, distance-scaled aim error, low-health medkit seeking and storm-edge retreat; offline fighters share spacing, strafing and storm avoidance. Clients count humans/bots from stored slot flags (the bot flag is only in full snapshots).
- Snapshots are compact (rounded numbers, private ammo fields only for humans, static name/team/outfit/bot fields once a second or on roster change, loot only when it changes); clients keep previous static values between full snapshots. The authority caches generated chunks (2048 fixed slots, O(1) eviction) and spawn checks use a separate probe chunk. Each match is capped at 30 participants; scale comes from many matches (`npm run bench` measures CPU and bandwidth). Public hosts stop polling and unlist once closed to joins.
- Multiplayer is authority-owned (dedicated server or the host's Worker) for PvP damage, ammo/range/cooldowns, shared props, collection and match results; clients do not award their own online damage/rewards. Room generation settings are locked to the first player. Offline NPC simulation is disabled online in favor of server-authoritative team bots. Keep remote storage fixed at 30 slots, reuse outgoing packet buffers, and clean sockets up on disconnect. Network event decoding is a documented allocation exception.
- The shared participant limit is src/match.ts MAX_PARTICIPANTS=30 (humans plus bots), with two teams of 15. Never count bot fill as extra human capacity. Public matchmaking must exclude private rooms, replace bots as humans join, and reject a 31st participant in a full human room. Eliminations are final in teams/br; friendly fire stays off. Render team colors. Bots and guests use player-style callsigns (src/names.ts) without BOT labels; guest callsigns persist on the device.
- Solo uses fixed pools of 26 hostile fighters and three friendly patrol bots plus the player, also capped at 30 characters. Projectiles and particles are not match participants.
- Ammo and medkit pickups are automatic on all devices and touch auto-opens nearby caches, but guns are never picked up or equipped automatically: they need E / COLLECT (auto touch collection sends an auto flag the authority honours), and taking a gun never changes the selected slot. Eliminated actors drop gun and ammo as separate items (ammo capped at 60) plus a MEDKIT_DROP_CHANCE medkit. Release joysticks on pointer up/cancel, lost capture, final touch end/cancel, resize, blur and visibility changes. Prevent accidental page gestures during play. Native fullscreen needs a user gesture and feature detection; keep a Home Screen fallback for iPad.
- Shared weapon/range/ammo and storm rules live in src/combat.ts. Seven firearms (carbine, shotgun, longshot, SMG, marksman, Sidekick, Vanguard) plus axe; always use FIREARM_MASK rather than literal bit masks. Projectile travel budget includes the muzzle offset and clips the final step. Land/water speed lives in src/entities.ts. Public matches enforce finite ammo. Infinite ammo and weapon masks belong only to private-party creation and must be enforced by authority, never trusted from shots.
- Elimination is final within a round in teams/br; only ffa/ctf respawn (RESPAWN_SECONDS, server-authoritative). Eliminated players in private rooms spectate living players (allies first) until an explicit winner; public teams/br elimination still ends the local round. Every newly started game uses a fresh seed and resets edits, caches, loot, storm, combatants, health, ammo and kills; purchased progress persists. Private host rematches keep members, code and rules, reset everyone to the lobby/ready handshake, and notify all members with a new round welcome. Only the host can restart; protect live multi-human rounds. Transfer host on leave. The storm shrinks, damages exposed actors, and the last surviving team wins. Preserve separate victory/loss screens and players-left/kill counters.
- Drops include the eliminated actor's current weapon and ammo; keep loot capped at 96 slots. Dropped guns render their local item illustration with a rarity glow; actors eliminated in a tick never pick up loot that tick. Local kills show a pooled flash/shockwave/coloured-spark/label effect in the equipped KILL_EFFECTS style plus a short camera shake (elimination events carry x/y). Round end runs a skippable finale: wins play the equipped victory dance full-screen, then a top-3 podium, then the results screen. Being outside the zone draws a pulsing storm-coloured screen border instead of the red hurt border. Server owns online pickups, kills, storm health and results. Concealment affects rendering and bot targeting; do not describe it as anti-wallhack security.
- Shop lists only unowned items and Locker only owned items; tab counts reflect exactly what each view lists. Categories: weapons, outfits, kill effects, victory dances (profile.buyCosmetic; free defaults Gold Burst / Victory Spin). Bots get a random outfit and a random allowed firearm per round (seeded hash offline, crypto randomInt on the server), and every actor renders the gun it holds.
- Locker displays only owned items and saves equipped starting weapon/outfit for the next match. Seven outfits and seven firearms have matching local previews. The axe must render as an axe and share axeReach forward-arc/surface-distance hit rules between local and server combat. Validate all firearm IDs; never hardcode a four-weapon upper bound or mismatch a bot mask candidate and its equipped weapon. Keep shop item images local in public/items, with descriptive alt text and previews matching actual weapon/outfit choices. Preserve responsive category filtering, ownership/equipped states, visible costs, and affordability checks. Shop assets must not add work to simulation ticks.
- src/profile.ts stores device-local coins/XP, weapon unlocks and cosmetic purchases. Keep validation and safe storage failure behavior; never make purchases drive negative balances. Save on progression changes / throttled HUD work, not every simulation tick. Device storage is not a protected online economy.
- Missing or malformed network winner/kills/weapon/ammo fields must never produce false losses, undefined UI or invalid WEAPONS indexing. Only explicit winner 0/1/2, winner 3 with an integer winnerId, or (public non-respawn rounds only) an entered player with confirmed zero health can finish a round. Validate unknown IDs and clear pending join timers on cancel/retry/error; guard duplicate joins.
- The only creator navigation is a small bottom Credits button on the start screen, leading to the static creator page public/about.html + public/about.css. No standalone About links or verbose creator section in the game UI. Credit Zain Abusal; bio/projects are sourced from https://zainabusal.dev. Preserve portfolio attribution, do not invent personal details.
- Do not deploy or publish unless requested. Hosting-ready does not mean deployed.
- Preserve user changes. Do not commit, push, or introduce cloud dependencies unless requested.

## Files

- src/world.ts: seed hashing, simplex noise, chunk layout, bounded edit persistence.
- src/landscape.ts: fixed terrain caches and prerasterized prop sprites.
- src/entities.ts: fixed-capacity structure-of-arrays Pool and player momentum.
- src/input.ts: hybrid input and virtual joysticks.
- src/engine.ts: loop, camera, culling, simulation, combat, rendering, telemetry.
- src/combat.ts: shared firearm statistics, storm radius and damage.
- src/session.ts: finite protocol defaults, explicit round outcomes, fresh client seeds.
- src/audio.ts: gesture-unlocked fixed Web Audio voice bank and mute lifecycle.
- src/profile.ts: device-local validated progression and purchases.
- src/match.ts: shared 30-participant/team-size limits, game modes, hostility and CTF constants.
- src/network.ts: transport-agnostic room lifecycle and fixed remote-player storage.
- src/authority.ts: transport-neutral room authority (rooms, combat, bots, modes, loot, snapshots).
- src/authority.worker.ts / src/p2p.ts: browser-hosted authority and WebRTC host/join transport.
- src/signal.ts / api/signal.ts / vite.config.ts: P2P signaling logic, Vercel Function and dev middleware.
- src/names.ts: player-style callsigns for guests and bots.
- server/index.ts: optional dedicated Node `ws` host around src/authority.ts.
- src/main.ts: application entry.
- src/style.css / index.html: HUD and responsive layout.
- vercel.json: static deployment configuration (api/ functions are zero-config).

## Verification

Run npm test and npm run build. For input/render changes run npm run test:browser (install Playwright Chromium first if unavailable). After changing fallback/audio/mobile chrome, build and run npm run test:production against the static dist output. For round lifecycle, network compatibility or axe changes run npm run test:scenarios as well. For P2P hosting/signaling changes run npm run test:p2p. Hardware acceptance still requires physical iPad Safari and a low-end laptop. Report measured evidence, not assumed FPS or heap guarantees. Keep PROJECT_PLAN.md acceptance checkboxes honest.
